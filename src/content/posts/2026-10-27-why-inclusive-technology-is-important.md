## First, a note about the web platform

Using the web platform as much as possible is the most inclusive approach to building websites. The more that we use tools to abstract away the platform, the more complicated we make the job.

For someone to write CSS using a framework, they still need to understand CSS. They will be able to get pretty far without understanding it, but eventually it will be needed. So, this means that both CSS and the framework must be understood. For anyone new to a project, this is a barrier.

React might be easier to understand than JavaScript, but if someone only learns React, their skills are not easily transferrable. If a new project uses Vue, that developer must learn Vue. Understanding JavaScript itself will get them a lot farther. If a project only needs a small amount of interactivity, using the platform is more inclusive. Anyone can make updates in the future, or review the code and learn from it.

## Why is being inclusive important?

Inclusive technology is the spirit of the open web. Bringing in the next generation of web developers is integral to the continued success of the web. If we use the web platform, we make it possible for those who come after us to learn from what we've done. The more we obscure away the “how” of a website, the harder we make it for others to learn.

More importantly, using the platform makes it incredibly straightforward to include use cases we might not even know about. There are many different screen readers, and many, many different assistive devices. Using the platform and meeting standards means that we include more of these users by default. At the moment, it’s not that we do not have a way to reach more people, it’s that we’re getting in our own way. Technology gives us the power to include in ways we’ve never been able to before, and it’s our moral imperative to take full advantage.

## But what about the bleeding edge?

The argument against inclusivity is always that it holds us back from using the latest and greatest. I think that an important part of this adjustment is redefining what latest and greatest means. Many new tools are not great. Often, they are designed for a specific use case, and have an opinionated perspective.

Often, the ability for someone to use something new and experimental is a great privilege. I know that my ability to use something new is built on top of years and years of experience, and the privilege of time. It can be alluring to go all in on this, but this is at the expense of closing the door to others. It's a way of pulling up the ladder behind me.

It's really difficult to "sell" the web platform, and so many of the new tools that come out have to be added on top of the web platform. Anytime that someone is selling something, they are incentivized to make it as complicated as possible. It might have great features, but by design, it isn't inclusive.

Lastly, the web isn't supposed to be about the bleeding edge. Yes, there are new features coming out all the time, and the Baseline project has done a lot to bring those features to all browsers, but we still have to make our choices based on what is actually available out in the real world.

## Inclusivity does not mean simple

I don't think that it's required that in order to be inclusive, we must make things as simple as possible. Simplicity can actually make things more complicated. Having options, different ways of going about things, and no single "right" path means that we are more open to contributions.

Getting back to the web platform, we don't have to worry about consistency as much when we are using the platform itself. It is a very forgiving platform, and many things are accepting of different approaches. That is its great strength.
